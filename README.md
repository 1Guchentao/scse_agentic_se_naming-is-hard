# Robot Navigation and Simulation

Group **naming-is-hard**

A robot receives blocked-path and goal-direction flags, chooses one safe move,
and is tested in four supplied environments. This repository follows that
decision from the original brief through requirements, planning, generated
Python, automated tests, simulation and review.

## The decision policy

The existing `navigate(obstacles, target=None)` helper is still the decision
core. It takes a clear target when one is available; otherwise it tries
FORWARD, LEFT, RIGHT, stopping when every direction is blocked.
`decide_next_move(state)` adapts the six boolean sensors to that helper.

The plan expresses two cases: `CLEAR_TARGET` and `NO_CLEAR_TARGET`.
When several goal flags are true, the adapter selects the first unblocked
indicated direction in FORWARD, LEFT, RIGHT order. This resolves an ambiguity
in the brief without adding a new robot action.

## Run locally

Use Python 3.10 or newer, from the repository root. On Windows:

```powershell
py -3.10 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-integration.txt
.\.venv\Scripts\python.exe -B verify_integration.py
.\.venv\Scripts\python.exe -B inspect_results.py
```

These checks read the saved evidence and run the single-step decisions.
They do not start Ollama. The offline regression suites are:

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -q
.\.venv\Scripts\python.exe -B -m pytest -q -p no:cacheprovider --import-mode=importlib integration_tests
```

To repeat the four routes with the revised code:

```powershell
.\.venv\Scripts\python.exe -B benchmark_irsim.py --code generated/navigation_logic_revised.py --output .local/routes
```

Choose an unused output directory. Each world gets its own report, console log,
measured poses, route PNG and GIF. The `.local` directory is ignored by Git.
For the teacher's original interactive display, run:

```powershell
.\.venv\Scripts\python.exe test_irsim_with_agent.py irsim_worlds/world_easy.yaml
```

That command uses the original Testing-stage policy. Replace the world filename
to inspect another supplied map. On Linux, use the same Python command with
your virtual environment's interpreter. The supplied `run_visual.sh` is retained
byte for byte, including its Windows line endings; use the Python entrypoint
instead of launching that shell file directly.

## A new model-driven run

The full workflow needs an existing Ollama installation and the already
downloaded `qwen2.5:3b` model. It generates new results rather than replaying
the saved responses:

```powershell
.\.venv\Scripts\python.exe -B main.py --allow-model --backend vulkan --device 1
```

Device 1 is the Vulkan NVIDIA device on the machine used here; it is not a
portable device number. Another compatible setup can use `--backend auto`.
A CPU-only model load is rejected. The private service runs one request at a
time, with two CPU math threads, RAM and GPU-temperature checks, and cleanup
on completion or failure. No cloud credential or model download is involved.

Read [the integration notes](docs/integration.md) before regeneration.
Only the revised round is published after its tests, simulations and reviews
pass. Unreviewed run folders stay local by default.
